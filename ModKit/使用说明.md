# Flotsam ModKit 使用说明

一套自研的 Flotsam（1.0.1f7 / Unity 6000.3.16f1 / Mono）mod 框架 + 五个功能模组。
地基是 **BepInEx 5.4.23.5 + HarmonyX**，上层是自研的 `FlotsamModKit` 管理器。

> 本文件对应 **v2**：四个模组在首轮实测后全部按根因重做（改动理由见 `设计与实现方案.md` §6）。

## 3. 安装 / 卸载 / 更新

```powershell
cd F:\Game\Flotsam\ModKit
.\build.ps1                 # 编译并安装到 F:\Game\Flotsam
.\build.ps1 -NoInstall      # 只编译
```

**卸载**

- 只删模组：删除 `Mods\flotsam.xxx\` 目录，或在管理器窗口点"卸载"（进 `.trash` 可找回）。
- 完全移除 ModKit：删除 `BepInEx\`、`Mods\`、`winhttp.dll`、`doorstop_config.ini`、`.doorstop_version`。
  这六项是**全部**新增内容——没有修改任何游戏本体文件。

## 4. 管理器窗口（默认 **F10**）

- **模组**：列出所有 mod（名称/版本/状态/补丁数）。`启用`/`禁用`立即生效（禁用会回滚该 mod 的全部补丁、订阅与 UI）；`卸载`需先禁用；`重载`重新扫描 `Mods\`（新装的 mod 无需重启游戏）。
- **按键**：所有 mod 注册的按键，点"改键"后按任意键改绑，自动存盘（Esc 取消）。
- **日志**：最近 400 行，按 mod 前缀区分；完整日志在 `BepInEx\LogOutput.log`。

改管理窗口按键：`Mods\ModKit.json` 的 `"managerKey": "F10"`。

> 诚实边界：Unity 的 Mono **无法卸载已加载的程序集**。"禁用"= 行为立即回滚，但代码仍在内存里；彻底释放内存需重启游戏。

## 5. 五个模组

### 5.1 键盘移动（`flotsam.keyboardmove`）

- **做什么**：世界地图**关闭**时，直接用键盘驾驶镇心（船）。
- **按键**：默认 `W/S/A/D`（自动沿用你已改过的原生镇心移动绑定），`F8` 暂停/启用。可在管理器改键。
- **原理（v2 修正）**：上一版有两处根本性错误——
  1. **一次 `MovementEvent.DispatchTownheartMove` 不是"移动原语"**：它唯一的监听者会重排瓦片内容，并连带**重建整块地形网格、清空寻路图、把每个漂流者 warp 一次**。每帧调用 = 持续重生成 → 你看到的"别的视角乱了"。
  2. `World.RepositionTownheart` **只接受"已生成瓦片范围内"的位置**，而瓦片只由 `WorldMap.LateUpdate` 生成（地图打开时才跑）→ 出界即被拒绝并抛异常 → "并没有真实移动"。
  v2 改为**后台地图（headless）**：把地图层级保持**激活**（让游戏自己的移动器跑物理、结算能量、继续生成瓦片），只**关闭它的画面**（地图相机 + 地图画布）；按键通过游戏自己的输入汇聚点 `FlotsamInputManager.GetMovementInput` 注入；世界位置按 **`commitInterval`（默认 0.15s）节流提交**，而不是每帧。
- **注意**：在世界视图里，**镇心本身不会位移**——这是原版的构造（世界内容是"城镇相对系"，`ReturnLocalToWorldPosition` / `RepositionRelativeToTownheart`），所以正确观感是**世界从船边滑过**。打开地图后位置与朝向一致。
- 进入后台模式后按地图键：先自动退出后台模式，再由原版正常打开地图（避免原版用未初始化的记账数据关地图）。
- **配置** `Mods\flotsam.keyboardmove\config.json`：

  | 键 | 默认 | 说明 |
  |---|---|---|
  | `mode` | `headless` | `headless`=后台地图（推荐）；`commit`=旧式直接提交（仅在 headless 不可用时） |
  | `speedMultiplier` | `1` | 速度倍率（0.1~8） |
  | `commitInterval` | `0.15` | 世界位置提交间隔（秒）。越小越顺滑但重生成越频繁；卡顿就调大 |
  | `hideMapPresentation` | `1` | 关闭地图相机与地图画布 |
  | `verbose` | `1` | 每次提交打印 `commit d=… `，方便确认是否真的在移动 |

### 5.2 建筑快速查找（`flotsam.buildingfinder`）

- **做什么**：屏幕右侧常驻按钮「建筑总览」（或按 `B`）打开：
  - **左侧 = 游戏原生的分类**：使用原生分类**图标**与**分类配色**，并显示每类数量；点击即筛选；
  - **右侧 = 建筑列表**：按游戏自己的排序规则（`SortBuildableList`）显示 图标 / 名称 / 建造中 / 故障数（`⚠ n`，来自原生 `PopulateMalfunctions`）；
  - **"全部"视图按分类分组**，每类一个彩色表头，不再是一坨平铺；
  - 搜索框支持 **名称 / I2 词条 / 分类名**（中英文均可）。
- **v2 修正**：分类以前在 `OnEnable` 里读取，而那时游戏还没进场景（`GameManager.Settings` 为空）→ 分类列表是空的，所以"全挤在一起"。现在改为**懒加载**：进存档后或首次打开面板时再读取并构建分类。
- **按钮与窗口可拖动并记忆**：HUD 按钮按住即可拖到任意位置，窗口可拖标题栏；位置写入该 mod 的 `config.json`。
- **配置**：`zoomLevel`(0.6)、`hideAfterFocus`(1)、`includeUnfinished`(1)、`groupAllByCategory`(1)、`maxRows`(400)、`draggableButton`(1)、`buttonX/buttonY`、`windowX/windowY`、`lastCategory`。

### 5.3 材料缺失辅助（`flotsam.materialhelper`）

- **做什么**：工坊缺料时一键去生产，**两个可靠入口**：
  1. **快捷键 `G`**（在工坊面板里）：对当前选中配方的缺料项安排生产；
  2. **配方列表每一行右侧的 `→生产 n` 按钮**（常驻、可点，n = 可生产的缺料项数量）。
- 动作：自动找到能生产该材料的**已完工建筑** → 相机飞过去 + 打开其生产面板 + 选中配方 + 数量 +1。`Alt`（配合点击/按键）= 填满队列，`Shift` = 连续生产。
- **为什么不用点缺料行（v2 修正）**：缺料行上的提示是**跟随鼠标的悬浮框**——`TooltipPanel` 每帧把浮层贴到光标右下 (15,5) 处，而且每个材料行在 `Awake` 都被挂上了 `ItemTooltip`。所以鼠标一靠近就出现、一移开就消失，**行本身永远点不到**；上一版的小标记还是 `raycastTarget=false`（根本不接收点击）。现在改挂在**常驻的配方行**上。
- 也**不能**用故障/警告图标当触发：那东西在"该配方已有排队"时会被抑制，而且每次排产尝试都会清掉再加，是闪烁的。
- **范围**：Workshop 类建筑（农场原版不显示缺料高亮）。
- **配置**：`zoomLevel`(0.6)、`showBadge`(1)、`startAmount`(1)、`altClickFillsQueue`(1)、`shiftClickContinuous`(1)。
- **为什么缺料也能排**：游戏自己的 `QueueRecipe` 在材料不足时干净地返回 false，而 `GameManager.LateUpdate` 每帧泵 `Producer.UpdateQueuedProducer()`——材料一到就自动预留并开工，不需要重试轮询。

### 5.4 可缩放小地图（`flotsam.minimap`）

- **做什么**（右侧，`M` 开关）：
  - **滚轮在光标处自由缩放**（0.2×~20×，锚点补偿，不会跑偏）；**拖拽平移**；**双击居中**；「适应世界」；**跟随镇心**开关（拖拽会自动关掉跟随）。
  - **底图 = 游戏真实的迷雾遮罩**（`WorldTile.FogOfWarAlphas`，逐顶点字节，代码里公开可读）+ 瓦片海域轮廓；
  - **标记 = 游戏自己的图标**（`ISpawner.Icon`：地标 / 兴趣点 / 漂浮垃圾），以 UGUI 图层绘制 —— 任意缩放下都清晰，未侦察的图标半透明；
  - 底部图例行显示各类数量；镇心用箭头显示**朝向**。
- **为什么不能直接复用原生地图**：原生地图瓦片在地图关闭后确实还活着，但挂在**被停用的父级**之下（`AddWorldTile` 用的是 prefab 的 parent），所以单独 `SetActive(true)` **什么都不渲染**；整棵重新激活又会连带它的移动器在暂停时驱动全局物理。因此改为"**用游戏自己的数据与图标重新合成**"。
- **配置** `Mods\flotsam.minimap\config.json`：

  | 键 | 默认 | 说明 |
  |---|---|---|
  | `textureSize` | `384` | 底图分辨率（128~1024） |
  | `refreshHz` | `8` | 重绘频率 |
  | `zoom` / `followTownheart` / `visible` | `1` / `1` / `1` | 初始缩放 / 跟随 / 默认显示 |
  | `showFog` | `1` | 是否绘制真实迷雾 |
  | `fogInvert` | `0` | **迷雾方向**。代码里无法判定"1=雾"还是"1=可见"；如果看起来该亮的地方黑、该黑的地方亮，把它改成 `1` |
  | `showIcons` / `iconSize` / `iconMinAlpha` | `1` / `20` / `0.45` | 图标开关 / 大小 / 未侦察时的透明度 |
   | `draggableButton` / `buttonX` / `buttonY` / `windowX` / `windowY` | — | 按钮与窗口位置（拖动后自动写入） |

### 5.5 游戏性调整（`flotsam.gameplaytweaks`）

- **做什么**：一个原生皮肤的滑块面板，把三项平衡改成"原版的百分比"，**100% = 原版**，拖动即时生效并记忆。按 `F7` 或点左上角「游戏性调整」按钮打开；窗口可拖动、可缩放、位置尺寸自动记忆；顶部有「总开关」（关掉=全部回原版）与「恢复默认」。
- **七个滑块**（分区）：
  - **重量**
    - `重量能耗影响`（0–300%）：城镇越重、移动越费电（本作重量**不降速**，只涨每单位距离的能量消耗）。**0% = 重量不再增加能耗**，100% = 原版，200% = 重量惩罚翻倍。
    - `载重上限倍率`（100–1000%）：抬高牵引/载重上限。**超重建不了新建筑**时调高它即可继续建（不改城镇实际重量，故与上一项互不影响）。
  - **发电**
    - `发电效率`（0–500%）：**所有发电机**（风/水被动、燃料、人力）的产出统一放大。
  - **美观度**（两层，各含正/负）
    - `负面建筑贡献`（0–200%）/ `正面建筑贡献`（0–500%）：缩放每栋建筑的美观分（负分建筑更温和、正分装饰更给力），直接改变城镇总美观分。
    - `负面士气修正`（0–200%）/ `正面士气修正`（0–500%）：缩放美观分对**居民士气**的正/负作用。
- **配置** `Mods\flotsam.gameplaytweaks\config.json`：`active`(1)、`weightEnergyPct`(100)、`tugCapacityPct`(100)、`generatorPct`(100)、`beautyNegBuildPct`(100)、`beautyPosBuildPct`(100)、`beautyNegMoralePct`(100)、`beautyPosMoralePct`(100)、`showPanel`(0)、`verbose`(0)、`button.*` / `panel.*`（位置尺寸，拖动后自动写入）。
- **已知边界**：重量分档面板显示的"eels/单位"、发电总览里每台机器的速率、建筑美观 tooltip 可能仍显示**基础值**，但**实际结算**（扣电、入网电量、城镇美观分与士气）按缩放走。

## 7. 开发一个新 Mod

1. 新建类库，引用（**`Private=false`**，不要把共享 DLL 拷进 mod 目录）：
   `Flotsam.ModKit.Abstractions.dll`、`Flotsam.ModKit.Game.dll`（外加 `Assembly-CSharp.dll` 等游戏程序集与 BepInEx/0Harmony）。
   目标框架 **netstandard2.1**（Unity 6 的程序集是 2.1，用 2.0 会报 `CS1705`）。最省事：复制 `src\mods\FlotsamMod.MiniMap\` 改名。
2. 实现入口：

```csharp
public sealed class MyMod : FlotsamModBase
{
    public override void OnLoad(IModContext ctx)      // 注册按键/配置（不碰游戏对象）
    {
        base.OnLoad(ctx);
        Keybinds.Register("mymod.toggle", KeyCode.F7, "开关");
        Log.Info("loaded");
    }

    public override void OnEnable()                    // 打补丁 / 订阅事件 / 建 UI
    {
        // 用 GamePatches 而不是 AccessTools.Method：后者在同名方法（含基类）存在时
        // 会抛 AmbiguousMatchException，一次就会让整个 mod 被标记为加载失败。
        var target = GamePatches.MethodByName(typeof(SomeGameClass), "SomeMethod");
        if (target == null) { Log.Error("目标未找到: " + GamePatches.Describe(typeof(SomeGameClass))); return; }
        Patches.Postfix(target, AccessTools.Method(typeof(MyMod), nameof(After)));
        Events.On("GameStart", _ => Ui.Toast("我的 mod 生效了", ToastKind.Success));
    }

    public override void OnDisable() { }               // 补丁/事件由宿主自动回滚；自建物体要销毁
    public static void After(object __instance) { }
}
```

3. 写 `mod.json`（示例见 `Mods\flotsam.minimap\mod.json`）：`id / name / version / apiVersion / entryAssembly / entryType / type(code) / keybinds[]`。
4. `.\build.ps1` 会装进 `Mods\<id>\`；游戏里 F10 →「重载」即可看到，无需重启。

**标准接口**（`IModContext`）：`Log`、`Config`、`Keybinds`、`Patches`（每 mod 独立 Harmony，禁用即整体回滚）、`Events`（自动退订）、`Ui`（Overlay/HUD 按钮/Toast）、`Control`。
**游戏侧门面**（`FlotsamModKit.Game`）：`GameApi`、`GamePatches`（安全目标查找）、`GameBuildings`、`GameProduction`、`GameMovement`、`GameWorld`、`GameKeys`、`GameUi`。

## 8. 请你实测的清单与已知限制

**最需要你确认的五点**（这次只验证到"加载 + 6 个补丁解析成功"）：

1. **键盘移动**：在地图关闭时按 `W/S/A/D`，看**世界是否从船边滑过**（镇心本身不位移是正常的），并看日志里是否持续出现 `commit d=…`。若日志没有 commit，请把 `verbose` 保持 `1` 并把日志发我。
2. **后台模式的副作用**：地图 UI/相机是否有残留；暂停、打字、打开其他面板时是否停手；按地图键是否正常进入真正的地图。
3. **建筑总览**：左侧是否出现带图标的分类、数量是否正确、"全部"是否按分类分组、按钮拖动后重启是否记住。
4. **`→生产 n` 按钮**：在工坊配方列表里是否可见、可点、点击后是否正确飞向生产者并排产。
5. **小地图迷雾方向**：若该亮处偏黑，把 `fogInvert` 改成 `1` 再看。
6. **游戏性调整**（`F7`）：面板 7 个滑块拖动是否顺滑、数值是否跟随；分别验证——重量能耗调到 0% 后移动是否不再因重量掉电、载重上限调高后超重能否继续建、发电效率调高后入网电量是否上升、美观四项调整后城镇美观分与居民士气是否随之变化；总开关关掉是否整体回原版；窗口缩放/拖动/隐藏帮助后重启是否记住。

**已知限制**：

- Mono 无法卸载程序集：禁用只回滚行为，内存需重启释放。
- 缺料行本身仍不可点（悬浮框机制所限），所以入口是快捷键 `G` 与配方行按钮。
- 农场（`Producer.Type.Farm`）不参与缺料辅助。
- 后台地图方案依赖"地图层级 + 私有 `_townheartPhysics` 字段"的现状；游戏大版本更新后可能需要同步更新 mod（失败会被管理器隔离并标红，不影响其他 mod）。
- 游戏本体是第三方整合包（含 Steam 模拟器、汉化改写过的 `resources.assets`），本套件**不做任何文件哈希校验**。
- `ModKit\src\_probe\` 是编译链路验证用的遗留工程，不参与安装，可删。
