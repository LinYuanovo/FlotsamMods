## 2. What breaks if the tiles are selectively re-activated

- `162441 — the blocker — a GameObject cannot render while an ancestor is inactive`. Because the tiles are children of the prefab's parent (159830), that ancestor is inside the `WorldMap` hierarchy; `SetActive(true)` on a `WorldMapTile` under an inactive root leaves the whole subtree non-rendering and non-updating in Unity. **Selective re-activation alone cannot work**: either the root (or the tile-parent subtree) is re-activated, or nothing shows.
- `163157 — WorldMapTile.Initialize — the expensive part is already done; re-activating needs no re-init`: it only registers `LandmarkSpawned`/`LandmarkDisposed`/`PointOfInterestSpawned` listeners and runs `InitializeCoroutine` (163218), which already ran and already did `base.gameObject.SetActive(value: true)` (163228). Re-activation therefore has no initialization dependency.
- `163224 — WorldMapTile — the sea transform/material state is baked per-tile and survives`: `_seaRenderer.sharedMaterial.SetFloat("_MapOverlayScale", worldTile.Scale);` — note `sharedMaterial`, so all tiles write the same material asset instance; with differing per-tile `worldTile.Scale` (157524, set from `_tileGenerator.Scale` at 157602) one value wins. Cosmetic only.
- `163174 — WorldMapTile.UpdateScouting — real per-frame work, uses Region/WorldTile data only`: `landmark.ScoutingState` / `SetScoutingState(ScoutingState.Scouted|Confirmed)` (163183-163196), ranges from `_defaultFOWRange 375` / `_defaultScoutRange 250` / `_watchFOWRange 750` / `_watchTowerScoutRange 250` (159574-159583). No dependency on the visuals being active — a re-activated subtree does not break scouting.
- `161960 — WorldMapLandmark.Scale — the one hard dependency on live camera state`: `Vector3.one * _scaleRange.Evaluate(GameManager.WorldMapManager.WorldMap.WorldCameraController.ZoomController.CurrentZoomLevel)` — `_scaleRange` initialized from `GameSettings.Instance.LandmarkSettings.MapScaling` (162307), default `new RangedFloat(0.5f, 1.5f)` (143252). Marker/landmark scale is a function of the *map camera* zoom, so visuals shown with the map closed need `CameraZoomController.SetZoom(...)`'s effect (35275 `SetZoom(ReturnSettings().Initial, overwriteDesiredZoom: true)` on Awake) or a scale the mod sets itself.
- `162808/162817 — WorldMapScoutableLandmark — coroutines and `isActiveAndEnabled` gating`: `SetScoutingStateCoroutine` uses `Tweener.TweenRoutine(...)` and `StartCoroutine`; the guards at 162782/162790/162796/162822/162830 read `base.isActiveAndEnabled` and `_rumoredVisual.gameObject.activeSelf`. A subtree re-activated without the game's close/open cycle can therefore *skip* a `→Scouted` visual transition (`case ScoutingState.Confirmed/Scouted:` at 162788 only shows the landmark when the component is inactive, the *opposite* of the intuitive condition, 162790).
- `162290 — WorldMapLandmarkMarker.Update — bearing-queue only, safe`: it dequeues when `!IsBearingFeatureActive(peek)` (162292). The marker's sprite renderers are driven only by compass events (`ActivateBearingTarget` → `_iconFront.sprite = bearingTarget.BearingIcon;` 162366, `_iconBack.sprite` 162367) and are otherwise `SetActive(false)` (162344/162386) — so this is **not** the per-landmark map icon; it is the compass-bearing marker.
- `161552 — WorldMapFogOfWar.Update — no real polling dependency`: body is only `if (_debugGradient || _debugRegion != null) UpdateAlphas(_debugRegion);`. Fog changes are pushed from static calls instead: `161565 ScoutArea` / `161573 ScoutRegion` iterate the static `_instances` list (161463), populated in `Initialize` when `!_isPadding` (161546-161549) and pruned in `OnDestroy` (161560-161562).
- `112081/112362 — real consumers of the map's active state`: `OnTownheartMoved(_worldMapTownheart.Position...)` and `(_worldMapTownheart.Initialized ? ... : World.TownheartWorldPosition)` — there is an "Initialized" twin of the townheart. I did not trace all of its call sites; any code that calls into the map while it is inactive is the main crash surface. **UNVERIFIED** in full.

## 4. Native sea/tile look

- `162899 — WorldMapSea` — `[SerializeField] private Material _dayMaterial;` (162904) / `_nightMaterial` (162907); per-instance `_meshFilter` (162924), `_defaultMesh`, `_meshRenderer` (162928), `_defaultMaterial`, `_defaultLocalScale`.
- `162949 — WorldMapSea.Initialize — day material is force-assigned, and the Voronoi flag is a shader int`: `_meshFilter.mesh = mesh;` / `_dayMaterial.SetInt("_IsVoronoi", 1); _nightMaterial.SetInt("_IsVoronoi", 1);` / `_meshRenderer.material = _dayMaterial;` (162959-162967), with `MAP_OVERLAY_IS_VORONOI_PROPERTY = "_IsVoronoi"` (162901) and the else-branch setting `0` (162982-162983). `Bounds` is captured from `worldTile.TryReturnWorldMapRegionMeshAndBounds(out mesh, out bounds)` (162952) — the real per-tile region mesh is available **only** via that method (157849, delegating to `_tileGenerator` 157855).
- `162936 — WorldMapSea.OnDestroy restores the borrowed mesh/material` — `_meshFilter.mesh = _defaultMesh; _meshRenderer.material = _defaultMaterial;`. **Nothing restores them on deactivation**, so the native look is still in place after a close. Practical point: `_meshRenderer.material` is a **clone** (not `sharedMaterial`), so sampling `_meshRenderer.material.mainTexture` per tile + `Bounds` is the viable "sea-like colours" path. Note I saw **no explicit texture field** in this class — the sea look comes from the material/shader; `mainTexture` content is **UNVERIFIED**.
- `163224 — WorldMapTile — `_seaRenderer.sharedMaterial.SetFloat("_MapOverlayScale", worldTile.Scale);` (see §2) and the renderer scale is `localScale.x = _fogOfWar.GridSizeX * _fogOfWar.TileSizeX; localScale.y = _fogOfWar.GridSizeZ * _fogOfWar.TileSizeZ;` (163221-163223). So sea/tile geometry is driven by the fog grid, which is itself derived from `WorldTile.FogOfWarBounds`.
- `157532 — WorldTile.WorldBounds => _worldBounds` (private `Rect _worldBounds`, 157502) vs `157520 — WorldTile.FogOfWarBounds { get; private set; }` and `157522 — WorldTile.FogOfWarAlphas { get; private set; }` (both `byte[]`/`Rect` getters).
  Populated at: `157603 — FogOfWarBounds = (_worldBounds = _bounds);` (after generation, with `Scale = _tileGenerator.Scale` 157602); `157623-157625 — RestoreFogOfWar(PersistentData)`: `FogOfWarBounds = (_worldBounds = persistentData.Bounds); FogOfWarAlphas = persistentData.Alphas; FogOfWarPersistentData = persistentData;`; `157630 — FogOfWarBounds = _bounds; FogOfWarAlphas = alphas;`.
  `157510 — FogOfWarPersistentData` is the save-path carrier: `161377 — WorldMapFogOfWar.PersistentData { Rect _bounds; byte[] _alphas; int _tileWidth; int _tileDepth; int _gridWidth; int _gridDepth; }` with public getters `Bounds`/`Alphas`/`TileWidth`/`TileDepth`/`GridWidth`/`GridDepth` (161391-161400), constructed from a live instance at 161403-161411.
- What the fog data actually IS: `161597 — GenerateMesh` sets `Bounds = bounds;` (161606) and `_meshBounds = new Rect(vector2.Vector2TopDown(), vector.Vector2TopDown());` (161607) where `vector = new Vector3(GridSizeX * TileSizeX, 0f, GridSizeZ * TileSizeZ)` and `vector2 = bounds.center.Vector3TopDown() - vector / 2f`; then `_colors[num] = Color.black;` (161629) and `RestoreAlphas(alphas, _colors, _vertexCount);` (161654), `_mesh.colors = _colors;` (161655). `161757 — ReturnAlphas()`: `array[i] = (byte)Mathf.FloorToInt(_colors[i].a * 255f);`. `161610-161612`: `_vertexColumnCount = gridSizeX + 1; _vertexRowCount = gridSizeZ + 1;` with `num = j + i * _vertexColumnCount` (161588 in `RestoreLastTileAlphas`).
  → **A mod can reconstruct the real fog state without any rendering**: `FogOfWarAlphas[v] / 255f` = the fog alpha of grid vertex `v`, laid out row-major over `(GridSizeX+1) × (GridSizeZ+1)` vertices spanning a rect of `(GridSizeX*TileSizeX) × (GridSizeZ*TileSizeZ)` centred on `FogOfWarBounds.center`. `GridSizeX/Z` and `TileSizeX/Z` are public on any live `WorldMapFogOfWar` (161489-161495); on the save path they come from `FogOfWarPersistentData`. Caveat: `RestoreLastTileAlphas` (161581-161595) writes alpha `1f` over the first `_tilePadding + 2` columns of each row, so tile padding is not real fog.
- **UNVERIFIED**: whether the fog shader multiplies by `vertexColor.a` with 1 = opaque fog or 1 = clear. `RestoreLastTileAlphas` writes `color.a = 1f` as the "restored/reset" state and `ScoutArea` *lowers* alpha to clear it, which reads as **1 = fog, 0 = explored** — but the shader was not inspected.

## 6. Better-than-flat drawing ideas grounded in the code

- `113066 — ChildBehaviourCache<T> : ChildObjectCache<T>` and `113082 — ChildObjectCache<T>` (serializable, `_prefab`/`_parent`/`_spawnParent`, `IReadOnlyList<T> Instances` 113097, indexer 113101) — a reusable enable/disable child pool; requires `[SerializeField]` wiring, so mostly useful as a pattern.
- `201560 — PrefabPool` / `201845 — PrefabPoolManager` / `201896 — ObjectPool<T>` — the game's runtime pooling; `161315 — WorldMapFlotsam.Update` uses `PrefabPool.GetInstance(_spawner.Properties.MapVisualPrefab, base.transform)`. Native map visuals can be pooled/reused this way if a mod wants the real 3D landmark models on its own map surface.
- `75852 — MarkerPanel : Panel` is **NOT a legend**: it is the drifter-assignment / marker-project panel (`_drifterCounter` 75868, `_radiusResizer` 75871, `_itemSlotPrefab` 75875). `75803 — CreateIcon(ItemProperties)` builds per-item icons into `_itemIconParent` via `GameManager.Settings.UISettings.MarkerIconPrefab` — a *pattern* for generating an icon grid, not a map legend. `MarkerIcon` (75557) is a UI widget.
- `160904 — WorldMapCompass` / `161043 — WorldMapCompassBearing` (`_iconRenderer.sprite = target.BearingIcon;` 161088) is the closest native "icon list": `[SerializeField] private ChildBehaviourCache<WorldMapCompassBearing> _bearings` (160910) over `List<IWorldMapCompassBearingTarget> _targets` (160918), rebuilt by `160929 UpdateBearings()`. It is a ring of bearing arrows around the townheart, not a legend, and **no native map legend UI exists** in this file.
- `161222 — WorldMapEnergyCostMarker` — `TextMeshPro _amountText` (161225) + `MeshRenderer _markerMeshRenderer` (161228), coloured per range (161257/161261) and rotated to the map camera in `Update` (161267-161269). Copyable pattern for camera-facing labels.
- 3D vs sprite reality check: on the native map, landmarks/POIs are **3D prefabs** (`163306 MapPrefab`, `161286 MapVisualPrefab`), and landmark footprint is a mesh outline (`162407 — WorldMapLandmarkPolygonVisual.Initialize` → `_meshRenderer.Initialize(list, material)` 162412, material from `GameManager.WorldManager.ReturnRegionProperties(spawner.RegionType)?.LandmarkMaterial` 162409). Only **bearing/compass/UI markers are sprites**. So "use the game's native display" for a Texture2D minimap splits into two very different things: (a) capture the native *rendered* map, or (b) composite native *icon sprites* — and the sprite set is smaller than it looks.
- Drawing `ISpawner.Icon` into a Texture2D is feasible: `Sprite.texture` + `Sprite.textureRect` are public Unity API (`Sprite.textureRect` is used by the game itself at 86107/229331/234783/300764). Do **not** call `GetPixels` on the sprite texture — see OPEN QUESTIONS.

## BEST NATIVE-LOOK ROUTE(S)

**Route A — one-shot RT capture of the live native map (best fidelity, highest cost).**
(a) APIs: `GameManager.WorldMapManager.WorldMap` (162418) → `WorldCameraController.Camera` (160644); `Camera.targetTexture`; `RenderTexture.GetTemporary`/`new RenderTexture(w,h,24)`; `WaitForEndOfFrame` then `RenderTexture.active` + `Texture2D.ReadPixels` + `Apply()` exactly as `79393-79399` does; trigger on `GameEventType.TransitionedToMapView` (`160363 — OnActivated`).
(b) Player sees: the *literal* native map — real Voronoi sea/region meshes (`_meshRenderer.material = _dayMaterial`, `_IsVoronoi=1`), real landmark/POI 3D visuals, real fog — thumbnailed into the minimap. This is unambiguously "the game's NATIVE display".
(c) Cost: high. Get the capture timing right (`Fade.InOut` at 160327/160338 means the map fades in before it is fully drawn), size the RT (needs to be large enough to stay legible when downscaled to a minimap), and re-capture per biome (`MoveToNextBiomeTask` destroys and rebuilds every tile, 160298-160307).
(d) Top risk: capture happens while `_isChangingState` is still true / during the fade, yielding a half-drawn or black frame — and the RT must be released (`_staticPortraitRenderTexture.Release()`, 79399) or VRAM leaks. **UNVERIFIED**: whether the map camera's `targetTexture` can be swapped for one frame without disturbing `CameraZoomController`/`_worldCameraPositionTweener` state.

**Route B — re-parent the tile-root and force the native tiles active, render on demand (live native tiles, medium-high cost).**
(a) APIs: the shared tile parent found through `_worldMapTilePrefab.transform.parent` (159830 — the exact object must be discovered at runtime, e.g. from `WorldMap._tiles[0].transform.parent`); `Transform.SetParent(null, true)`; `SetActive(true)` on that subtree; then `CameraZoomController` zoom state for `WorldMapLandmark.Scale` (161960) / `MapScaling` `RangedFloat(0.5f, 1.5f)` (143252); `WorldMapTile.UpdateScouting` (163174) and `WorldMapFogOfWar.ScoutArea` (161565) keep working because they read `WorldTile`/`_instances` data only.
(b) Player sees: the real sea/region meshes plus the real landmark models, updating as scouting advances — a genuinely live native minimap, not a snapshot.
(c) Cost: medium-high but conceptually simple; no pixel readback.
(d) Top risk: fighting the game's own state machine — `Deactivate()` → `PruneWorldtiles()` (159754/159854) and `MoveToNextBiomeTask`'s `Object.Destroy(tile.gameObject)` (160300) will destroy or orphan a re-parented subtree; the `isActiveAndEnabled` gates in `162782/162790` can leave landmarks permanently hidden; and anything still holding `WorldMap` assumptions (e.g. 112081/112362) may misbehave. This must be undone cleanly before `WorldMap.Open()`.

**Route C — keep the procedural texture, but composite native sprites + real fog (lowest cost, biggest legibility win per hour).**
(a) APIs: icons via `IWorldMapMarkerTarget.Icon` (158251, sampled from any live `WorldMapMarker` at 162542) and `ISpawner.BearingIcon` (139257/139377/139686) / `LandmarkSettings.ReturnBearingIcon` (143284); POI icons directly via `PointOfInterestSpawner.Icon → Properties.DebugIcon` (139901/48079); landmark icons need reflection for `LandmarkBehaviour._uiIcon` (101668, `internal`); sprite pixel size from `Sprite.textureRect` and atlas-safe UVs from the `textureRect / texture.width|height` pattern (86107, 234785, 300764); fog via `WorldTile.FogOfWarAlphas` (157522) / `FogOfWarPersistentData.Alphas` (161377/161393) indexed `v = j + i*(GridSizeX+1)` over a `(GridSizeX*TileSizeX) × (GridSizeZ*TileSizeZ)` rect centred on `FogOfWarBounds.center` (161597-161612, 161757-161770).

**Ranking: C first (cheap, directly answers the complaint), then B (the real native look), then A (maximum fidelity, most fragile).** A/C combine well: C for the always-on minimap, A for a one-time "real map" layer captured the first time the player opens the map.
